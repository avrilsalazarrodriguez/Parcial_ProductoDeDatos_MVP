# Texto sugerido para el reporte

La aplicación final combina inferencia interactiva y resultados batch precomputados. Para inferencia individual, Streamlit carga el modelo serializado `model.joblib` dentro del contenedor y predice para un par tienda-producto seleccionado. Para batch grande —por ejemplo catálogo completo, todos los productos de una tienda o una categoría— la aplicación no ejecuta el modelo en cada clic; en su lugar lee pronósticos precomputados desde S3 bajo `modelops/latest/`. Esta decisión reduce latencia percibida por el usuario, evita saturar el contenedor de Streamlit y permite que el CFO descargue archivos grandes sin esperar un entrenamiento o scoring pesado.

El flujo de ModelOps corre fuera de Streamlit con SageMaker Processing. Genera features, entrena modelos globales y segmentados, evalúa contra un baseline naive y escribe forecast/evaluación en S3. La app en ECS Fargate consume esas tablas con `boto3`, usando permisos del Task Role. Las credenciales de RDS no están hardcodeadas: se leen desde Secrets Manager. RDS se usa para feedback de negocio, productos problemáticos e historial de exports CFO. Glue Data Catalog cataloga las tablas de S3 para que BI pueda hacer cortes adicionales.

El sistema mantiene separación de responsabilidades: SageMaker Processing se usa para cómputo pesado, S3/Glue para persistencia analítica, ECS Fargate/ECR para servir la UI, RDS para datos operacionales y Secrets Manager para credenciales. Esta arquitectura responde a los requisitos de latencia, costo, trazabilidad, observabilidad y usabilidad del MVP.
